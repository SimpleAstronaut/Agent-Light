# Agent Light 0.2.1 使用手册

适用：Windows 11 x64 桌面版。更新日期：2026-11-08。

Agent Light 把 DSH 的运行、等待、失败和完成状态显示到 USB 三色灯板上。桌面程序负责后台服务、设备连接和状态管理。**打开桌面程序后，无需再单独运行 `agent-light serve`。**

## 1. 安装与快速开始

从 [GitHub Release](https://github.com/SimpleAstronaut/Agent-Light/releases/tag/v0.2.1-preview.1) 下载 `AgentLight-0.2.1-windows-x64-setup.exe`，按安装向导操作后，从开始菜单打开 Agent Light。

默认安装位置为 `%LOCALAPPDATA%\Programs\AgentLight`。如果选择便携版，解压 `AgentLight-0.2.1-windows-x64.zip`，打开其中的 `AgentLight` 文件夹并运行 `AgentLight.exe`。

完整目录需要保留；`_internal` 和 `resources` 都是程序依赖，不能只复制一个 exe。桌面分发包无需另外安装 Python 或 PySide6。仓库开发者也可以在构建完成后运行 `pc/dist/AgentLight/AgentLight.exe`。

安装、升级和卸载的具体步骤见[安装手册](installation-guide.md)。此版本为预览版，验收范围见第 13 节。

首次使用按以下顺序操作：

1. 如果原来正在终端运行上位机 `serve`，回到该终端按 `Ctrl+C`，等待服务退出。安装或修改接入前，也要退出对应的 DSH Web 后端。
2. 打开 Agent Light，等待状态页显示“服务在线”。
3. 接入 USB 灯板，在“设备”页扫描并连接，等待“灯板已确认”。
4. 点击三色测试，查看阶段记录，并观察实物红、黄、绿灯。
5. 在“Agent 接入 → DSH”页检测 DSH，安装接入配置，然后重新启动 DSH。
6. 回到状态页，等待“DSH 上报”显示“上报正常”，再用一次实际对话观察业务灯态。

关闭浏览器中的 DSH 网页标签不代表后端已经退出。在启动 DSH Web 的终端按 `Ctrl+C`，等待返回命令提示符，再确认已退出。

## 2. 首次启动与旧服务切换

首次启动会创建配置；已经存在的配置、token、数据库和 outbox 会继续使用，不会自动重置。

如果出现 `SERVICE_ALREADY_RUNNING`：

1. 检查是否已经有 Agent Light 桌面窗口或托盘图标。
2. 若原先使用终端启动后台服务，先在原终端正常退出它。
3. 若是另一个桌面实例，从托盘选择“退出 Agent Light”，等待清理结束后再启动。

同一 Windows 用户只运行一个桌面实例。再次打开程序会激活现有窗口；携带不同配置启动时，会提示 `CONFIG_INSTANCE_CONFLICT`，需要先退出原实例再切换。

## 3. 连接灯板

打开左侧“02 设备”。

### 自动发现

1. 插好灯板，点击“扫描”。
2. “连接方式”选择“自动发现”。
3. 只有一块匹配设备时，点击“保存并连接”。
4. 等待状态页显示“灯板已确认”，或设备页显示“确认：已确认”。

“保存并连接”返回成功只表示连接意图和配置已接受，仍需等待实际设备确认。

### 手动指定

如果连接了多块灯板，或需要指定某个端口：

1. 选择“手动指定端口”。
2. 点击“扫描”，从“串口”下拉框选择目标端口。
3. 目标端口未显示时，可勾选“显示全部串口（包括不匹配的设备）”，再点一次“扫描”。
4. “序列号筛选”可留空；填写时必须与目标设备一致。
5. 点击“保存并连接”，等待确认。

端口号以当前扫描结果为准，不固定为某个 COM 号。扫描仅枚举设备，不会逐个试开串口。

点击“断开”会停止自动重连。需要恢复时，重新点击“保存并连接”。一般通信故障会自动重试连接。

### 三色测试

1. 等待灯板已确认，测试按钮可用。
2. 点击“开始红 → 黄 → 绿三色测试”。
3. 程序依次发送红、黄、绿，每个颜色收到设备 ACK 后保持至少一秒。
4. 最后恢复测试结束时的最新业务灯态。
5. 成功时显示“灯板已确认完成三色测试”；下方保留各阶段的 ACK 和保持记录。

测试期间不能保存显示配置，可以断开设备、切换连接或退出程序，这些操作会终止测试。测试不会修改 Agent 会话。ACK 表示设备确认了命令，实际灯是否亮起仍需观察实物。

## 4. 将 DSH 接入灯板

打开左侧“03 Agent 接入”，再选择二级选项“DSH”。需要选择以下三个实际文件：

| 界面字段 | 应选择的文件 |
|---|---|
| DSH lib/bin.js | 你的 DSH 安装目录中，`@deepseek-ai/dsh/lib/bin.js` 对应的入口 |
| 该 DSH 的 Node | 启动这套 DSH 使用的 `node.exe` |
| dsh-web.ps1 | 你日常启动 DSH Web 所用的受支持包装脚本 |

可以先点击“重新检测”尝试自动发现；未发现时点击“浏览…”选择文件。Node 应来自该 DSH 环境。移动 DSH 或换电脑后，需要按实际安装位置重新选择。

### 检测

1. 点击“重新检测”。程序会尝试自动发现，也可以点击“浏览…”手动选择上述三个文件。
2. 检查显示的入口、Node、版本和兼容结果。
3. 只有显示宿主版本与指纹兼容，才继续安装接入。

当前插件门禁对应 DSH 0.2.1-rc.2、Cordis 4.0.5，并检查固定文件指纹。只修改版本号不能通过检查。

### 安装或迁移旧接入

1. 正常退出所有加载此插件的 DSH Web 后端。
2. 可先点击“生成接入配置”查看草稿位置。**仅生成草稿不会启用插件。**
3. 点击“安装 / 更新接入”。程序会再次检测宿主并生成待修改内容。
4. 核对弹窗中的目标启动脚本、正式 overlay、插件路径和差异。
5. 确认 DSH 已退出，勾选确认框，再点击确定。
6. 等待提示“接入配置已安装，重启 DSH 后生效”。
7. 使用原来的 `dsh-web` 入口重新启动 DSH。

使用 PowerShell 时，可按实际位置启动，例如：

```powershell
& "C:\Your DSH Folder\bin\dsh-web.ps1"
```

已识别的旧无标记接入会按预览迁移，原启动脚本会备份。遇到“不支持的启动脚本”或文件并发修改提示时，先停止修改、核对脚本，不要盲目再追加一份接入。

### 验证实际上报

重新启动 DSH 后，回到“状态”页：

1. 来源明细应出现 DSH producer，并出现本次运行收到的心跳时间。
2. “DSH 上报”应显示“上报正常”。
3. “灯板确认”应独立显示“灯板已确认”。
4. 发起一次 DSH 对话，观察业务状态和实物灯态是否随运行、完成而变化。

“配置已生成”“配置已安装”“宿主兼容”和“上报正常”分别表示不同进展。安装成功后仍需重启 DSH，并收到真实心跳。

## 5. 看懂状态与灯效

状态页四张卡片分别表示：

| 卡片 | 含义 |
|---|---|
| 本地服务 | 桌面程序能否访问本地后台服务 |
| DSH 上报 | 已登记的 DSH 来源是否健康，并有本进程接受的心跳 |
| 灯板确认 | 当前连接的命令与设备返回状态是否一致且有效 |
| 业务灯态 | 当前所有参与来源和会话汇总后的业务状态 |

例如，“服务在线、DSH 未上报、灯板已确认”表示设备链路已就绪，可以继续排查 DSH 接入；“DSH 上报正常、灯板未连接”则应检查 USB 连接。

| 实物灯效 | 业务/设备状态 | 含义 |
|---|---|---|
| 全灭 | IDLE | 空闲，或完成保持时间已到 |
| 黄灯常亮 | RUNNING | 正在运行 |
| 红灯常亮 | ATTENTION | 等待审批或回答问题 |
| 红灯闪烁 | ERROR | 任务错误，或来源异常、失联 |
| 绿灯常亮 | COMPLETED | 任务完成，正在保持完成提示 |
| 黄灯闪烁 | WAIT_SYNC / LINK_LOST | 设备等待同步或与上位机失去通信 |

多会话聚合优先级为：异常 → 等待处理 → 运行中 → 完成 → 空闲。因此，一个来源的失联或一个会话的错误，可能盖过其他会话的运行/完成提示。可查看来源明细和设备模式区分原因。

刷新失败后，界面会把插件和设备快照标为过期/未知；连续失败后显示服务离线。

## 6. 调整亮度、完成保持和启动行为

打开左侧“04 设置”。

### 显示设置

1. 调整“亮度（%）”，范围 20–100，默认 35。
2. 设置“完成保持”，单位秒，默认 300；填写 0 表示不保持完成提示。
3. 点击“保存并应用显示配置”。
4. 等待“配置已保存，后台已应用”的提示，设备同步结果再看状态页。

完成保持时间的修改只影响之后的新完成事件，不会重新计时已有的完成提示。空闲状态始终全灭。

### 开机启动和托盘

- 勾选“登录 Windows 时启动并驻留托盘”，使桌面分发版在当前用户登录时启动。
- 勾选“关闭窗口时保持后台运行”，关闭窗口后继续保持服务和灯板链路。
- 源码运行模式没有稳定安装入口时，开机启动选项不可用。
- 使用便携版启用开机启动后，应保留程序所在目录；若移动目录，需重新设置启动项，并核对 DSH 接入路径。

## 7. 日常使用与退出

完成首次接入后，日常顺序为：启动 Agent Light → 确认灯板连接 → 启动 DSH → 正常使用。

已启用关闭驻留时，关闭窗口会隐藏到托盘。可从 Windows 任务栏托盘或其隐藏图标区域找到 Agent Light，打开主界面、运行测试或进入设置。

要完全停止后台服务，右键托盘图标，选择“退出 Agent Light”，等待清理结束。未启用关闭驻留时，关闭窗口也会执行完整退出。

退出过程中若显示“正在退出”或清理超时，应等待在途操作结束；不要反复开启新实例或删除活动锁文件。

## 8. 停用旧来源与重新启用

当某个 DSH 来源已经永久停止、旧 producer 仍在来源明细中并导致租约过期异常时：

1. 确认对应 DSH 采集器已经退出。
2. 等待其租约过期，通常需距最后心跳超过 15 秒。
3. 在状态页选中准确的 producer 行。
4. 点击“停用来源”，核对身份和影响后确认。

停用会排除该来源及旧会话的灯态贡献，同时保留历史。仍有其他异常来源时，灯板可能继续显示异常。仍在上报的来源不能停用；服务刚重启后的登记窗口内也可能需要等待。

需要恢复该来源时：选中对应行 → “重新启用来源” → 确认 → 重启对应 DSH。界面会先显示恢复中，收到新的运行身份及健康心跳后才恢复正常。

不要仅为了消除红灯停用仍需使用的来源；先查看失联或上报异常的原因。

## 9. 解除接入、升级和卸载

### 解除 DSH 接入

1. 退出对应 DSH Web 后端。
2. 在“Agent 接入 → DSH”页点击“卸载接入”。
3. 核对差异，确认已退出 DSH，再执行。
4. 需要继续使用 DSH 时，重新启动它。
5. 若该旧来源已不再使用，可按第 8 节显式停用。

### 升级程序

1. 从托盘完整退出 Agent Light，并退出加载此插件的 DSH。
2. 运行新安装包。便携版也必须在退出后整体更新目录。
3. 新版本启动后检查服务、设备连接及插件路径；Agent 接入 → DSH 页面需要更新接入时，先查看差异再确认。
4. 重新启动 DSH，核对上报状态。

### 卸载程序

安装版从 Windows“设置 → 应用 → 安装的应用”找到 Agent Light 并卸载。卸载前退出 Agent Light 和相关 DSH。

卸载会先检查本安装目录已登记的 DSH 接入，并要求确认解除。取消操作、启动脚本被修改或记录异常时，会中止卸载，先按提示核对。

配置、token、数据库、outbox、overlay 和备份会保留。手工创建且未登记的 overlay 引用，也需要自行解除。便携版移除目录前，同样先解除其 DSH 接入和开机启动项。

## 10. 数据位置与自定义配置

默认数据目录：

```text
%LOCALAPPDATA%\AgentLight\
├─ config.json            后台配置
├─ token                  本地鉴权凭据
├─ state.sqlite3          状态与历史
├─ dsh-outbox\            DSH 待上报队列
├─ integrations\          接入草稿、正式 overlay 和记录
└─ backups\               接入修改备份
```

可以在资源管理器地址栏输入 `%LOCALAPPDATA%\AgentLight` 打开。token 文件用于本地鉴权，Agent 接入 → DSH 页面填写的是相关文件路径，不需要复制 token 内容。

桌面开关和上次选择的路径按 Windows 用户保存，不在后台 config.json 中。运行期间应通过界面修改显示和串口设置；直接修改 config.json 后，需退出并重新启动程序加载。

需要自定义配置时，可从 PowerShell 启动：

```powershell
$agentLightInstall = Join-Path $env:LOCALAPPDATA 'Programs\AgentLight'
& "$agentLightInstall\AgentLight.exe" --config "C:\My Agent Light\config.json"
```

自定义配置的接入文件位于该配置父目录的 `integrations/<配置路径摘要>/` 中；在 Agent 接入 → DSH 页面点击“打开配置目录”可直接找到。不同配置各自隔离，切换前先完整退出现有桌面实例。

备份数据时，先退出 Agent Light 和对应 DSH，再复制实际配置指向的数据目录；自定义数据可能位于默认目录之外。

## 11. 可选命令行操作

图形界面运行时，可用同目录的 `agent-light.exe` 查询。以下以默认安装位置为例：

```powershell
$agentLightInstall = Join-Path $env:LOCALAPPDATA 'Programs\AgentLight'
& "$agentLightInstall\agent-light.exe" health
& "$agentLightInstall\agent-light.exe" status
& "$agentLightInstall\agent-light.exe" test
```

若桌面使用自定义配置，CLI 也要传同一个 `--config`：

```powershell
& "$agentLightInstall\agent-light.exe" --config "C:\My Agent Light\config.json" status
```

`clear` 可以清除会话中已记录的错误/完成状态；它不会解除来源失联、待审批/待回答或 USB 连接问题。来源永久停止时，使用界面的来源管理操作。

CLI 的 `test` 返回成功只表示测试已接受，最终结果仍需查看设备页。

常见退出码：0 为命令成功；1 为网络或一般错误；2 为参数错误；3 为测试设备未就绪/已有测试；4 为鉴权失败。

## 12. 常见问题

| 现象/错误码 | 操作 |
|---|---|
| SERVICE_ALREADY_RUNNING | 正常退出旧 CLI 服务或桌面实例，再启动；不要删除活动锁 |
| ENDPOINT_IN_USE | 核对本地服务端口是否被其他程序占用；不要同时启动多个相同端口的服务 |
| CONFIG_INSTANCE_CONFLICT | 从托盘退出现有实例后，再使用另一配置启动 |
| DEVICE_NOT_FOUND | 检查供电、USB 数据连接和端口枚举，再扫描；必要时明确选择实际端口 |
| DEVICE_NOT_UNIQUE | 有多个匹配设备，改为手动指定，或填写唯一序列号 |
| DEVICE_IDENTITY_MISMATCH | 重新核对端口与序列号；留空序列号会清除旧筛选 |
| DEVICE_NOT_READY / 测试按钮不可用 | 等待灯板确认；检查设备页诊断及实际模式 |
| DISPLAY_TEST_RUNNING | 等待测试完成后再保存显示配置，或断开设备终止测试 |
| HOST_NOT_FOUND | 在 Agent 接入 → DSH 页面重新选择 DSH 的 `lib/bin.js` |
| NODE_RUNTIME_MISSING | 选择该 DSH 使用的 Node 可执行文件 |
| UNSUPPORTED_VERSION | 核对宿主版本与检测结果；不要忽略指纹不匹配 |
| 配置已安装，但 DSH 未上报 | 使用选中的 dsh-web 入口重启后端，检查来源明细是否收到当前心跳 |
| PRODUCER_STILL_REPORTING | 正常退出对应采集器并等待租约过期，再停用准确的来源 |
| CONFIG_CHANGED_EXTERNALLY | 完整退出并重新启动服务加载外部修改 |
| INSTALLER_CONCURRENT_CHANGE | 文件在预览后变了，重新检测和预览后再决定 |
| INSTALLER_UNSUPPORTED | 启动脚本不属于受支持模板；先核对脚本，改用手工接入方案 |
| INSTALLER_ROLLBACK_REQUIRED | 按安装记录与备份核对文件，完成前保留插件目录 |
| SHUTDOWN_TIMEOUT | 程序仍在等待资源释放；保留当前实例，避免重复启动 |
| AUTH_FAILED | 核对 GUI 和 CLI 是否使用同一个配置及其 token 文件 |

## 13. 当前版本范围

“Agent 接入”的二级导航包含 DSH、Codex、ZCode、WorkBuddy。DSH 提供完整的现有配置操作；Codex 页面可点击“检测环境”，但真实事件适配仍未实现；ZCode、WorkBuddy 暂为待适配说明页，相关操作禁用。

选择不同 Agent 只切换页面，不会卸载或停止 DSH，也不设置“只能运行一个 Agent”的模式。返回 DSH 时保留当前输入和检测结果；DSH 的原有路径偏好、接入记录和数据位置不变。

本版已通过自动化回归、本机源码外分发运行、真实 DSH 版本/指纹的只读检测及模拟负载验证。真实灯板、真实 DSH 迁移链路、Windows 登录自启、交互式安装/卸载和第二台机器的验收尚未全部完成，详情见[实施与验收记录](superpowers/plans/2026-11-08-desktop-ui-progress.md)。
